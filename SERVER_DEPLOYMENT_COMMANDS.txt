문제: git pull 시 "unstaged changes" 에러 발생

해결: 변경사항을 stash하고 다시 pull

================================================================================
방법 1: 자동 스크립트 사용 (추천)
================================================================================

서버에서 다음 명령어를 복사해서 실행하세요:

bash <(cat << 'SCRIPT'
#!/bin/bash
cd /root/uvis/frontend
echo "1️⃣ 현재 변경사항 임시 저장 (stash)..."
git stash push -m "Auto stash $(date +%Y%m%d_%H%M%S)"
echo "2️⃣ 최신 코드 가져오기..."
git pull origin main
echo "3️⃣ dispatch-rules.ts 확인..."
grep -A 2 "rule_update: payload" src/api/dispatch-rules.ts && echo "✅ Fix 확인됨!" || echo "❌ Fix 없음"
echo "4️⃣ 빌드..."
npm run build
cd /root/uvis
echo "5️⃣ Docker 이미지 재빌드..."
docker-compose build uvis-frontend
echo "6️⃣ 컨테이너 재시작..."
docker-compose restart uvis-frontend
sleep 10
echo "7️⃣ 로그 확인..."
docker logs uvis-frontend --tail 20
echo ""
echo "🎉 배포 완료!"
echo "브라우저에서 http://139.150.11.99/dispatch-rules 테스트하세요!"
SCRIPT
)

================================================================================
방법 2: 수동 단계별 실행
================================================================================

1. 변경사항 임시 저장:
   cd /root/uvis/frontend
   git stash

2. 최신 코드 가져오기:
   git pull origin main

3. 수정사항 확인:
   grep "rule_update: payload" src/api/dispatch-rules.ts

4. 빌드:
   npm run build

5. Docker 재빌드:
   cd /root/uvis
   docker-compose build uvis-frontend

6. 재시작:
   docker-compose restart uvis-frontend

7. 로그 확인:
   docker logs uvis-frontend --tail 20

================================================================================
방법 3: 변경사항 무시하고 강제 덮어쓰기 (주의!)
================================================================================

현재 로컬 변경사항을 모두 버리고 GitHub의 최신 코드로 덮어씁니다:

cd /root/uvis/frontend
git fetch origin main
git reset --hard origin/main
npm run build
cd /root/uvis
docker-compose build uvis-frontend
docker-compose restart uvis-frontend

⚠️ 주의: 로컬의 모든 변경사항이 사라집니다!

================================================================================
배포 후 테스트
================================================================================

1. 브라우저 캐시 클리어
   - Chrome: Ctrl+Shift+Delete
   - "캐시된 이미지 및 파일" 체크 → 삭제
   - 또는 시크릿 모드 사용

2. URL 접속
   http://139.150.11.99/dispatch-rules

3. 규칙 수정 테스트
   - 기존 규칙 선택
   - "수정" 버튼 클릭
   - 이름 또는 우선순위 변경
   - 저장
   - ✅ 성공 메시지 확인!

4. 개발자 도구 확인 (선택사항)
   F12 → Network 탭
   - PUT 요청 찾기
   - Payload: {"rule_update": {...}} ✅
   - Response: 200 OK ✅

================================================================================
API 직접 테스트
================================================================================

서버에서 curl로 직접 테스트:

curl -X PUT http://localhost:8000/api/v1/dispatch-rules/1 \
  -H "Content-Type: application/json" \
  -d '{"rule_update": {"name": "테스트_'$(date +%s)'", "priority": 888}}' | jq .

기대 응답:
{
  "id": 1,
  "name": "테스트_1234567890",
  "priority": 888,
  "version": N
}

================================================================================
문제 해결
================================================================================

문제: 빌드 실패
해결: npm install && npm run build

문제: Docker 빌드 실패
해결: docker-compose build --no-cache uvis-frontend

문제: 컨테이너가 시작되지 않음
해결: docker logs uvis-frontend --tail 50

문제: 여전히 422 에러
해결: 
  1. 브라우저 캐시 완전 삭제
  2. 시크릿 모드로 테스트
  3. F12 → Network 탭에서 Payload 확인
