Test 1: Local Build Exists?
────────────────────────────────────────────────────────────────────────────

Command:
   ls -lh /root/uvis/frontend/dist/index.html
   ls /root/uvis/frontend/dist/assets/*.js | wc -l

✅ Good output:
   -rw-r--r-- ... /root/uvis/frontend/dist/index.html
   82

❌ Bad output:
   ls: cannot access '.../index.html': No such file or directory
   0

→ If bad: Run `cd /root/uvis/frontend && npm run build`


Test 2: Container Files Exist?
────────────────────────────────────────────────────────────────────────────

Command:
   docker exec uvis-frontend sh -c "ls /usr/share/nginx/html/assets/*.js | wc -l"

✅ Good output:
   82

❌ Bad output:
   0
   ls: /usr/share/nginx/html/assets/*.js: No such file or directory

→ If bad: Files not copied to container = Docker COPY problem


Test 3: Referenced Files Match?
────────────────────────────────────────────────────────────────────────────

Command:
   # What does index.html reference?
   docker exec uvis-frontend grep 'src="' /usr/share/nginx/html/index.html
   
   # Does that file exist?
   docker exec uvis-frontend ls -lh /usr/share/nginx/html/assets/index-*.js

✅ Good output:
   <script ... src="/assets/index-B5F1Uvtw.js"></script>
   -rw-r--r-- ... 284K ... /usr/share/nginx/html/assets/index-B5F1Uvtw.js

❌ Bad output:
   <script ... src="/assets/index-B5F1Uvtw.js"></script>
   ls: /usr/share/nginx/html/assets/index-*.js: No such file or directory

→ If bad: File referenced but doesn't exist = COPY failed


Test 4: Browser Network Tab
────────────────────────────────────────────────────────────────────────────

In browser:
   1. Press F12
   2. Go to Network tab
   3. Refresh page (Ctrl+R)

❌ Bad output:
   index-B5F1Uvtw.js   404   ...      js   ...

Root Cause 1: Wrong Path in Dockerfile
════════════════════════════════════════════════════════════════════════════

❌ WRONG:
   FROM node:18 AS builder
   WORKDIR /app
   RUN npm run build          # Creates /app/dist/
   
   FROM nginx:alpine
   COPY --from=builder /app/build /usr/share/nginx/html/
                       ^^^^^^^^^^
                       Wrong path! Should be /app/dist/

✅ CORRECT:
   FROM node:18 AS builder
   WORKDIR /app
   RUN npm run build          # Creates /app/dist/
   
   FROM nginx:alpine
   COPY --from=builder /app/dist /usr/share/nginx/html/
                       ^^^^^^^^^
                       Correct!

How to check:
   cat /root/uvis/frontend/Dockerfile | grep "COPY.*html"


Root Cause 2: .dockerignore Blocking
════════════════════════════════════════════════════════════════════════════

❌ PROBLEM:
   # frontend/.dockerignore
   node_modules
   dist              ← Blocks dist/ folder!
   build
   .env

✅ FIXED:
   # frontend/.dockerignore
   node_modules
   .env
   # dist           ← Removed!
   # build          ← Removed!

How to check:
   grep -E "^dist$|^build$" /root/uvis/frontend/.dockerignore

Should output nothing (or lines commented with #)


Root Cause 3: Multi-stage Build Missing COPY
════════════════════════════════════════════════════════════════════════════

❌ PROBLEM:
   FROM node:18 AS builder
   WORKDIR /app
   COPY . .
   RUN npm run build
   
   FROM nginx:alpine
   # Missing: COPY --from=builder !

✅ FIXED:
   FROM node:18 AS builder
   WORKDIR /app
   COPY . .
   RUN npm run build
   
   FROM nginx:alpine
   COPY --from=builder /app/dist /usr/share/nginx/html/

How to check:
   cat /root/uvis/frontend/Dockerfile

Symptom: Container has 0 JS files
Cause: Docker COPY failed
Solution:
   1. Check Dockerfile COPY path
   2. Check .dockerignore doesn't block dist/
   3. Run: bash EMERGENCY_FIX.sh
   OR
   4. Quick: docker cp frontend/dist/. uvis-frontend:/usr/share/nginx/html/


Symptom: Container has files, but browser shows 404
Cause: File hash mismatch
Solution:
   1. Compare local vs container index.html
   2. Rebuild: docker-compose build --no-cache frontend
   3. Ensure fresh copy of all files


Symptom: Browser shows cached old version
Cause: Browser cache
Solution:
   1. Ctrl+Shift+Delete → Clear cache
   2. Close ALL browser windows
   3. Test in incognito mode


Symptom: Files exist, but layout still broken
Cause: CSS not loading or JS error
Solution:
   1. F12 → Console → Check for errors
   2. F12 → Network → Check CSS/JS load status
   3. Verify OrdersPage.tsx JSX closing tag
